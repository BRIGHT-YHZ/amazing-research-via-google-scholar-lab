## ✨ 项目亮点

### 🚀 一键环境部署及启动，无需繁琐命令行
- 提供 `run_secure_exe.bat`，推荐双击启动
- 无需手动配置复杂命令行环境
- 更适合直接分发给团队成员或合作方使用

### 🖥️ UI 交互友好，使用更直观
- 提供前端页面进行交互，降低使用门槛
- 相比纯命令行方式，更适合日常科研人员操作
- 输入问题、启动任务、查看流程都更直观
- 更方便演示、交接、团队内部推广与协作

### 🧠 多问题批量处理，提升调研效率
- 支持一次输入多个研究问题
- 适合选题探索、方向对比、综述前期筛查等场景
- 减少重复搜索、重复整理、重复切换上下文

### 📦 问题级目录隔离 + PDF 分批下载
- 每个问题独立建立目录
- 每个问题按自己的流程单独处理与保存
- 下载过程更清晰，结果更易复核、复用与追踪
- 即使任务中途中断，也更容易保留已完成部分

### 📝 Markdown 格式元数据导出，方便后续投喂 AI
- 每个问题独立生成 `metadata.md`
- 更方便后续：
  - 投喂 AI 做文献总结
  - 提炼与研究问题相关内容
  - 形成阅读笔记与研究备忘
  - 支撑后续 AI 辅助综述写作
- 相比散乱 PDF，更利于二次整理和知识沉淀

## 🔬 项目定位

本项目聚焦于**科研工作流效率优化**，希望把文献相关流程尽量串成一条稳定链路，而不只是单纯“下载 PDF”。

核心流程是：

> **研究问题 → 检索结果 → AI提炼与问题相关文献内容 → 元数据归档 → PDF下载 → AI辅助综述**

它特别适合以下场景：

- 课题前期调研
- 多个研究问题并行筛查
- 综述资料整理
- AI 辅助的文献摘要、归纳、对比分析

## 📌 当前工作方式

- 支持一次输入多个问题进行批量处理
- 支持按问题独立组织结果目录
- 支持 AI 提炼与当前研究问题相关的文献内容
- 每个问题可独立导出 `metadata.md`
- 每个问题对应 PDF 可分批下载
- 已完成问题的结果不会混入其他问题目录
- 即使中途终止，也更容易保留已完成批次结果

## 📂 输出结构示例

```text
downloads/
  *sessiontime*_*sessionid*_SESSION/
    *sessiontime*_*sessionid*_Q01_meta/
      metadata.md
      *.pdf
    *sessiontime*_*sessionid*_Q02_cohort/
      metadata.md
      *.pdf
```

### 结构说明
- `SESSION`：一次完整运行会话
- `Q01 / Q02`：问题级批次编号
- `metadata.md`：当前问题对应的元数据归档文件
- `*.pdf`：该问题下载得到的文档

这种结构更适合：
- 回看某一条研究问题的检索结果
- 比较多个问题之间的文献差异
- 将单题结果直接投喂 AI 做针对性总结或综述

## 🤖 为什么强调 Markdown 元数据导出

相比把信息散落在浏览器、剪贴板或临时笔记中，`metadata.md` 更适合科研与 AI 场景：

- **结构清晰**：便于阅读、归档、版本管理
- **可直接复用**：适合转为综述草稿、阅读笔记、证据表
- **天然适配 AI**：可以直接投喂给大模型做总结、提炼、对比与综述生成
- **问题级隔离**：每个问题一份独立资料，减少上下文污染

适合的后续用法包括：

- 文献总结与问题相关内容提炼
- 文献综述初稿生成
- 研究进展速览
- 不同机制 / 方向的对比归纳
- 证据链条整理
- 课题讨论底稿准备
